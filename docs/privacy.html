Privacy Policy

Last updated: 29 September 2026 · Applies to the browser extension “Full Page PDF Snap” for Firefox and Chrome.

This extension collects no data. It has no server and contains no analytics or telemetry code. It makes exactly one network request: before each capture, the time anchor fetches a public random value from the drand network (api.drand.sh, drand.cloudflare.com, api2.drand.sh) so the capture time can be verified afterwards. This is on by default. Nothing of yours is sent — no address, no page content, no identifier — but like any HTTP request it reveals your IP address and the time to whoever answers it.

What data is collected

None. The developer receives no information of any kind — not which pages you capture, not the resulting PDF files, not usage statistics, not error reports.

What stays on your device

The extension stores your settings locally through the browser’s own storage API — output folder, filename template, JPEG quality, scroll delay, PDF format, resolution scaling and a counter for sequential filenames. This data never leaves your device and is removed when you uninstall the extension.

The generated PDF files are written to the download folder you chose. They are ordinary files under your control.

Why the permissions are needed

You can switch it off in Firefox's extension settings; it will then ask again the next time you start a capture. On Chrome it is still requested per click, for the current tab only. On either browser it is only used while a capture runs, and only for the page you started it on — nothing is read in the background and no page content is sent anywhere.

Third parties

One: the drand network, for the time anchor described above. Apart from that, no external services, no content delivery networks, no fonts or scripts loaded from elsewhere, no advertising, no third-party libraries that phone home.

The citation endpoint on provinglab.dev

Everything above covers the extension. The website additionally runs a public endpoint (/mcp) that fetches citation data from addresses its callers name. When a page does not declare enough itself, the endpoint may additionally ask Crossref, DataCite, the German National Library, PsychArchives or the EU Publications Office about the identifier in question — those services then see that this identifier was looked up, and from which Cloudflare location. adoption_stats reads a public download figure from addons.mozilla.org, open_work reads public issues from api.github.com. No caller data is passed on in any of these requests. It runs as a Cloudflare Worker with the platform’s request logging (Cloudflare Workers Logs) switched on.

  • What is stored: for each request, an invocation log with the request method and URL, the response and related technical metadata — the content is documented by Cloudflare. Beyond Cloudflare's own logging, the worker keeps one counter of its own: it increments a tally per tool name for each tool call, and a tally per client name — as the client reports it — for each opened session. This is stored in Cloudflare KV for 90 days. No address, no arguments, no page content and no user identity are recorded. Only the number of distinct clients is published through adoption_stats — the names themselves are not handed out. All of this is verifiable in the published source code.
  • Where: in the operator’s Cloudflare account, in the Workers Logs of that worker.
  • How long: the project operates the worker on the Workers Free plan, under which Cloudflare keeps logs for a maximum of 3 days; on the Workers Paid plan the maximum is 7 days (source: Cloudflare Workers Logs documentation, retrieved 3 August 2026).
  • What does not happen: the logs are not analysed into usage profiles, not combined with other data and not passed to third parties. They exist for error diagnosis and for detecting abuse of the open endpoint.

Verification

The complete source code is published under the MIT license at github.com/Bubu89/full-page-pdf-snap. The submitted extension files are the source files — no bundler, no minification — so what you audit is what runs.

Datenschutzerklärung

Stand: 29. September 2026 · Gilt für die Browser-Erweiterung „Full Page PDF Snap“ für Firefox und Chrome.

Diese Erweiterung erhebt keine Daten. Sie hat keinen Server und enthält keinen Analyse- oder Telemetriecode. Sie stellt genau eine Netzwerkanfrage: Vor jeder Aufnahme holt der Zeitanker einen öffentlichen Zufallswert vom drand-Netz (api.drand.sh, drand.cloudflare.com, api2.drand.sh), damit der Aufnahmezeitpunkt später nachweisbar ist. Das ist standardmäßig eingeschaltet. Übermittelt wird nichts von Ihnen — keine Adresse, kein Seiteninhalt, keine Kennung — aber wie jede HTTP-Anfrage verrät sie dem Empfänger IP-Adresse und Zeitpunkt.

Welche Daten erhoben werden

Keine. Der Anbieter erhält keinerlei Informationen — weder welche Seiten Sie erfassen, noch die erzeugten PDF-Dateien, noch Nutzungsstatistiken oder Fehlerberichte.

Was auf Ihrem Gerät bleibt

Die Erweiterung speichert Ihre Einstellungen lokal über die Speicher-API des Browsers: Zielordner, Dateinamen-Vorlage, JPEG-Qualität, Scroll-Wartezeit, PDF-Format, Auflösungs-Skalierung und einen Zähler für fortlaufende Dateinamen. Diese Daten verlassen Ihr Gerät nicht und werden bei der Deinstallation entfernt.

Die erzeugten PDF-Dateien werden in den von Ihnen gewählten Download-Ordner geschrieben. Es sind gewöhnliche Dateien unter Ihrer Kontrolle.

Dritte

Einen: das drand-Netz, für den oben beschriebenen Zeitanker. Sonst keine externen Dienste, keine Content-Delivery-Netzwerke, keine von außen geladenen Schriften oder Skripte, keine Werbung, keine Fremdbibliotheken, die nach Hause telefonieren.

Der Zitations-Endpunkt auf provinglab.dev

Alles bis hier betrifft die Erweiterung. Die Website betreibt zusätzlich einen offenen Endpunkt (/mcp), der Zitationsdaten von Adressen abruft, die Aufrufende nennen. Gibt eine Seite zu wenig selbst preis, fragt der Endpunkt zusätzlich bei Crossref, DataCite, der Deutschen Nationalbibliothek, PsychArchives oder dem EU-Amt für Veröffentlichungen nach der betreffenden Kennung — diese Dienste sehen dann, dass nach dieser Kennung gesucht wurde, und von welchem Cloudflare-Standort aus. adoption_stats liest eine öffentliche Downloadzahl bei addons.mozilla.org, open_work öffentliche Vorgänge bei api.github.com. Bei keiner dieser Anfragen werden Daten des Aufrufers weitergegeben. Er läuft als Cloudflare Worker mit eingeschalteter Anfragen-Protokollierung der Plattform (Cloudflare Workers Logs).

  • Was gespeichert wird: je Anfrage ein Protokolleintrag mit Methode und Adresse der Anfrage, der Antwort und zugehörigen technischen Metadaten — der Inhalt ist von Cloudflare dokumentiert. Über Cloudflares eigene Protokollierung hinaus führt der Worker einen eigenen Zähler: Für jeden Werkzeugaufruf erhöht er eine Zählung nach Werkzeugname, für jede eröffnete Sitzung eine nach dem Client-Namen, wie ihn der Client selbst angibt. Das liegt 90 Tage in Cloudflare KV. Weder Adresse noch Argumente, Seiteninhalt oder Nutzeridentität werden erfasst. Veröffentlicht wird über adoption_stats allein die Anzahl verschiedener Clients — die Namen selbst werden nicht herausgegeben. Das alles ist im veröffentlichten Quelltext nachprüfbar.
  • Wo: im Cloudflare-Konto des Betreibers, in den Workers Logs dieses Workers.
  • Wie lange: das Projekt betreibt den Worker im Tarif Workers Free, in dem Cloudflare Protokolle höchstens 3 Tage aufbewahrt; im Tarif Workers Paid beträgt das Maximum 7 Tage (Quelle: Dokumentation zu Cloudflare Workers Logs, abgerufen am 3. August 2026).
  • Was nicht geschieht: die Protokolle werden nicht zu Nutzungsprofilen ausgewertet, nicht mit anderen Daten verknüpft und nicht an Dritte weitergegeben. Sie dienen der Fehlerdiagnose und dem Erkennen von Missbrauch des offenen Endpunkts.

About this website

The policy above covers the browser extension. This website (provinglab.dev) is a separate matter and is described here for completeness.

  • The site is static, hosted on GitHub Pages behind Cloudflare DNS. It sets no cookies, embeds no third-party scripts, no analytics library and no advertising.
  • Like every web server, the hosting provider records access data (IP address, time, requested page, user agent) for delivery and abuse prevention. We do not combine these with anything and cannot identify individual visitors.
  • Requests to the citation endpoint additionally pass through a Cloudflare Worker whose platform keeps request logs. What they contain, where they are kept and for how long is set out above under The citation endpoint on provinglab.dev.
  • Should measurement of visits ever be added, it will be a cookieless method, and this section will say so before it goes live.
